Every EvalZero service: the GitHub repo to clone, the command that **installs/builds** it, and the
command that makes it **live**. All repos are under [`github.com/prativahq`](https://github.com/prativahq).

## Repositories

| Service | Repository | Folder |
| --- | --- | --- |
| LMS app | `prativahq/evalzero-sunbird-lms` | `evalzero-sunbird-lms` |

| Knowlg content | `prativahq/evalzero-sunbird-knowlg-service` | `knowlg` |

### Clone everything

```bash
mkdir -p ~/evalzero && cd ~/evalzero
git clone https://github.com/prativahq/evalzero-sunbird-local-infra.git sunbird-local
git clone https://github.com/prativahq/evalzero-sunbird-lms.git
git clone https://github.com/prativahq/evalzero-sunbird-inquiry.git
git clone https://github.com/prativahq/evalzero-sunbird-knowlg-service.git knowlg
git clone https://github.com/prativahq/evalzero-sunbird-userorg.git
git clone https://github.com/prativahq/evalzero-sunbird-rc.git
```

## Install & make live

| Service | Install / build | Make it live |
| --- | --- | --- |
| **Infra** | `cd sunbird-local` | `docker compose up -d` |
| **LMS app** | `cd evalzero-sunbird-lms && npm install` | `npm run dev` |
| **inQuiry** | Docker-Maven build → dist ([setup](/inquiry/setup)) | `docker start assessment-service search-service` |
| **Knowlg** | Docker-Maven build → dist ([setup](/knowlg/setup)) | `docker start knowlg-content` |
| **UserOrg** | `./build-and-run.sh` ([setup](/auth/userorg#fresh-machine-build)) | `docker start lern-userorg` |
| **Keycloak** | *pre-provisioned container* | `docker start kc_postgres kc_local` |
| **RC** | `cd evalzero-sunbird-rc` | `docker compose up -d` |
| **Email** | *shared listmonk container* | `docker start sahyogi_listmonk_app listmonk_db` |

<Note>
  Two kinds of "install": **compose** services (infra, RC) create their containers on first
  `docker compose up`. **Play/Scala** services (inQuiry, Knowlg, UserOrg) must be **built once**
  (Docker Maven → Play dist → `docker run`) — after that, `docker start <name>` is all you need. The
  full build recipe is documented for inQuiry in [Fresh Machine Setup](/inquiry/setup); the other
  Play services follow the same pattern.
</Note>

## Why some start with `docker start`, not compose

Only two folders own a `docker-compose.yml` EvalZero uses: `sunbird-local` (infra) and
`evalzero-sunbird-rc` (credentials). The Play/Scala services were each built once into a standalone
container, so `docker compose up` in `sunbird-local` never touches them — start those with
`docker start <name>`.

<Warning>
  Keycloak (`kc_local`) and its database (`kc_postgres`) are **not** part of the `sunbird-local`
  compose project, so `docker compose up -d` won't start them. And `kc_postgres` (Keycloak's DB,
  internal `:5432`) is a *different* Postgres from `sunbird-local-postgres-1` (`:5433`). See
  [Auth → Keycloak](/auth/keycloak).
</Warning>
