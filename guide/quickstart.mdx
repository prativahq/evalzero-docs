EvalZero LMS is the app you run — the Sunbird services are its backing stack. If those are
already up, one command starts EvalZero.

<Info>
  All paths are under **`~/evalzero`**. The LMS server runs on **`:3002`**.
</Info>

## Already running? Run EvalZero

<CodeGroup>
```bash EvalZero
cd ~/evalzero/evalzero-sunbird-lms
npm run dev            # EvalZero → server :3002 + Vite client
```
</CodeGroup>

Cold machine? Bring up the three backing layers first, then run EvalZero.

## Cold start — three layers

<Steps>
  <Step title="Infra stack — databases, storage & Kafka">
    ```bash
    cd ~/evalzero/sunbird-local
    docker compose up -d
    ```
    Brings up Cassandra, Neo4j, Redis, Elasticsearch, PostgreSQL, MinIO, Zookeeper and Kafka.
    See [Infrastructure](/infra/overview) for the full port map.
  </Step>

  <Step title="Sunbird microservices — start the existing containers">
    ```bash
    docker start \
      kc_postgres kc_local \
      lern-userorg \
      knowlg-content \
      assessment-service search-service schema-http
    ```
    On **this dev box** these containers were already built, so `docker start` is all you need.

    <Warning>
      `docker start` only starts an **existing** container. On a **fresh machine** these don't
      exist yet — `docker start` returns *No such container*. You must **create** them first (build
      → `docker run`, or `docker compose` for infra + RC), and only then does `docker start` apply.
      Rebuild recipes live in each service's folder — see
      [inQuiry → Startup](/inquiry/startup) for the assessment/search build.
    </Warning>
  </Step>

  <Step title="Run EvalZero (this checkout)">
    ```bash
    cd ~/evalzero/evalzero-sunbird-lms
    npm install            # first time only
    npm run dev            # server :3002 + Vite client
    ```
  </Step>
</Steps>

<Note>
  The server runs on `:3002` — the Vite dev server's default proxy target — so `npm run dev` works
  with no extra env. Running a **second** checkout alongside? Give it a different `PORT` and point
  its client at it, e.g. `VITE_API_TARGET=http://localhost:3010 VITE_DEV_PORT=5174 npm run dev -w client`.
</Note>

## Health checks

```bash
curl -s localhost:9010/health | jq   # assessment (cassandra+neo4j+redis)
curl -s localhost:9011/health | jq   # search (elasticsearch)
curl -s localhost:9099/health | jq   # knowlg content
curl -s localhost:9600/health | jq   # userorg
```

<Tip>
  Want the microservices to survive a reboot?
  `docker update --restart unless-stopped kc_postgres kc_local lern-userorg knowlg-content assessment-service search-service`
</Tip>
