The **inQuiry assessment-service** is the Sunbird Question &amp; QuestionSet API. EvalZero uses it
to author, play and grade assessments. It runs against the shared `sunbird-local` infra.

## QuML — the content format

inQuiry speaks **QuML (Question Markup Language)** — Sunbird's open, player-agnostic spec for
representing questions and question sets. Every authored object is a QuML document, stored in
Cassandra/Neo4j and **validated against a QuML JSON schema** on every create/update.

Two object types:

| Object | `mimeType` | What it is |
| --- | --- | --- |
| **Question** | `application/vnd.sunbird.question` | A single item — MCQ, subjective, fill-in-the-blank |
| **QuestionSet** | `application/vnd.sunbird.questionset` | An ordered collection of questions (and nested sub-sets) |

The fields that make a QuML object:

| Field | Meaning |
| --- | --- |
| `primaryCategory` | The category definition it binds to — e.g. `Multiple Choice Question`, `Practice Question Set`. Must be seeded (see [Dependencies](/inquiry/dependencies)) or `create` fails. |
| `interactions` | How the learner answers (`choice`, `text`, …) |
| `responseDeclaration` | The correct answer + per-question scoring (`maxScore`, `cardinality`, `correctResponse`) |
| `outcomeDeclaration` | Set-level scoring rules (aggregation across questions) |
| `body` / `editorState` | The rendered question markup + the authoring UI state |

<Note>
  Validation runs against `schemas/<objectType>/1.0/` (mounted at `/app/schemas/`). A payload that
  doesn't match the QuML schema returns `Validation Errors` → `SERVER_ERROR`. The most common cause
  is sending create fields at the wrong nesting level (they must sit under `request.question` /
  `request.questionset`) or an unseeded `primaryCategory`.
</Note>

## What it stores

Questions and question sets split across two databases:

| Store | Holds |
| --- | --- |
| **Neo4j** | Node metadata + graph relationships (`domain` label, `IL_UNIQUE_ID`) |
| **Cassandra** | Heavy "external" props: body/answer blobs, `interactions`, `responseDeclaration`, `editorState` (JSON) |

The split logic lives in knowlg-core `DataNode.scala` (`getExternalProps` / `saveExternalProperties`).

## API surface

| Route | Purpose |
| --- | --- |
| `POST /question/v4/create` | Create a question |
| `GET /question/v4/read/:id` | Read a question |
| `POST /questionset/v4/create` | Create a set |
| `PATCH /questionset/v4/hierarchy/update` | Save questions inline |
| `GET /questionset/v4/hierarchy/:id?mode=edit` | Read the draft tree (needs search) |

## EvalZero wiring

The LMS proxies `/api/question/*` and `/api/questionset/*` to `:9010` via
`server/src/routes/inquiry.routes.ts`, plus secure `/play` + `/submit` endpoints that grade
server-side. See [Scoring](/inquiry/scoring).
