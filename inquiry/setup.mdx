title: inQuiry — Fresh Machine Setup
description: Clone and run build-and-run.sh to build the assessment service and bring it up on a brand-new machine.
---

The **from-scratch** path: clone → `./build-and-run.sh`. The script does the whole recipe —
build → dist → assemble runtime → patch config → Cassandra schema → run → verify — in one shot.
On a machine that already has the containers, use [Startup](/inquiry/startup) instead (just
`docker start`).

<Info>
  Everything builds with **Docker Maven** (no host JDK/Maven needed) and runs as containers on the
  shared `sunbird-local_default` network. Target folder: `~/evalzero/evalzero-sunbird-inquiry`.
  Assessment on **:9010**, search on **:9011**.
</Info>

## Prerequisites

<Steps>
  <Step title="Docker + the infra stack">
    Docker installed, and the `sunbird-local` infra up (Cassandra, Neo4j, Redis, Elasticsearch,
    MinIO, Kafka). The `sunbird-local_default` network must exist.
    ```bash
    cd ~/evalzero/sunbird-local && docker compose up -d
    docker network ls | grep sunbird-local_default
    ```
  </Step>
  <Step title="knowlg-core artifacts in ~/.m2">
    The assessment build reuses Knowlg's `knowledge-platform` `_2.13` artifacts (graph-engine,
    graph-core, cloud-store-sdk…). Build the [`knowlg`](/knowlg/setup) service first so
    `~/.m2/repository/org/sunbird/**` is populated, or the Maven build fails.
  </Step>
</Steps>

## Build & run

```bash
cd ~/evalzero
git clone https://github.com/prativahq/evalzero-sunbird-inquiry.git
cd evalzero-sunbird-inquiry
chmod +x build-and-run.sh
./build-and-run.sh
```

That's it. A healthy `:9010/health` at the end means the whole chain — build, config, Cassandra
columns, category defs — is wired. The LMS reaches it via `INQUIRY_BASE=http://localhost:9010`.

### Flags

| Invocation | Effect |
| --- | --- |
| `./build-and-run.sh` | Full run: Docker-Maven build → dist → runtime → schema → run → verify |
| `SKIP_BUILD=1 ./build-and-run.sh` | Reuse the existing dist zip — skip the (slow) `mvn` build/dist |
| `RUN_SEARCH=1 ./build-and-run.sh` | Also (re)run `search-service` on :9011, if `search-runtime/` exists |

## What the script does

<Steps>
  <Step title="0 · Preflight">
    Checks Docker is up, the `sunbird-local_default` network exists, and Cassandra / Neo4j / Redis /
    Elasticsearch are running. Warns if `~/.m2` has no `org.sunbird` artifacts.
  </Step>
  <Step title="1–2 · Build + dist (Docker Maven)">
    `mvn clean install` for all modules, then `play2:dist` for `assessment-service` →
    `assessment-service-1.0-SNAPSHOT-dist.zip`. Skipped when `SKIP_BUILD=1` and the zip is present.
  </Step>
  <Step title="3 · Assemble runtime">
    Lays out `assessment-runtime/` = extracted dist + `config/` + `schemas/`. Because the Maven
    container runs as **root**, `target/` is root-owned — the script `sudo cp`s the zip out to a
    user-owned folder before unzipping (the same root-owned-`target/` trap the build scripts guard).
  </Step>
  <Step title="4 · Patch application.conf">
    Rewrites hosts to the `sunbird-local` containers — Cassandra `sunbird-local-cassandra-1:9042`,
    Redis `sunbird-local-redis-1`, Neo4j `bolt://sunbird-local-neo4j-1:7687`, Kafka
    `sunbird-local-kafka-1:29092`, `schema.base_path=/app/schemas/`, and
    `composite.search.url=http://search-service:9000/v3/search`.
  </Step>
  <Step title="5 · Cassandra schema (idempotent)">
    Runs `scripts/cassandra-db/apply-schema.sh` — applies `cassandra.cql`, then **check-then-`ALTER`**
    for the assessment columns (`outcomeDeclaration`, `feedback`) that Knowlg-created shared tables
    may lack. See the warning below.
  </Step>
  <Step title="6 · Category-definition check">
    Verifies the question/questionset category rows exist in
    `dev_category_store.category_definition_data`. Warns (does not fail) if they're missing — seed
    them or `create` returns `ResourceNotFoundException`. See [Dependencies](/inquiry/dependencies).
  </Step>
  <Step title="7 · Run + verify">
    Starts the `assessment-service` container (host **9010** → container **9000**) and polls
    `/health` until Cassandra + Neo4j + Redis are green. `RUN_SEARCH=1` also starts `search-service`
    on :9011.
  </Step>
</Steps>

<Warning>
  The `dev_question_store` / `dev_hierarchy_store` keyspaces are **shared with Knowlg**, which may
  create their tables *without* the assessment columns. A plain `CREATE TABLE IF NOT EXISTS`
  no-ops, so `apply-schema.sh` checks `system_schema.columns` and `ALTER`s only the missing ones
  (Cassandra 3.11 has no `ALTER … ADD IF NOT EXISTS`). Safe to re-run. **Never** run `nodetool
  resetlocalschema` on this single node — it wipes every schema definition.
</Warning>

## search-service (:9011)

The editor/player need `questionset/v4/hierarchy/:id?mode=edit`, which calls composite search, so
`search-service` must be running for **edit** reads. It's built separately from the knowlg
`knowledge-platform` (`search-api/search-service`, same Docker-Maven → `play2:dist`) and extracted
to `search-runtime/`. Once that exists, `RUN_SEARCH=1 ./build-and-run.sh` brings it up, or run it
directly:

```bash
docker run -d --name search-service --network sunbird-local_default -p 9011:9000 \
  -v $PWD/search-runtime/search-service-1.0-SNAPSHOT:/app/dist:ro \
  -v $PWD/search-runtime/config:/app/config:ro \
  -w /app --platform linux/amd64 eclipse-temurin:17-jre \
  sh /app/dist/start -Dhttp.port=9000 -Dpidfile.path=/dev/null \
  -Dconfig.file=/app/config/application.conf -Dlogger.file=/app/config/logback.xml
```

Its `config/application.conf` needs `search.es_conn_info = "sunbird-local-elasticsearch-1:9200"`
and `play.modules.enabled += modules.SearchModule` (or Guice fails to bind `SearchActor`). Create
the empty `compositesearch` ES index — hierarchy reads work immediately; result rows fill once the
Flink indexer runs.

## Verify

```bash
curl -s localhost:9010/health | jq   # cassandra + neo4j + redis → all healthy
curl -s localhost:9011/health | jq   # elasticsearch → healthy (if search is running)

# create → read a question
curl -s -X POST localhost:9010/question/v4/create \
  -H 'Content-Type: application/json' \
  -d '{"request":{"question":{"code":"smoke-q-1","name":"Smoke","mimeType":"application/vnd.sunbird.question","primaryCategory":"Multiple Choice Question"}}}' | jq .result.identifier
```

A `do_…` identifier back means the full stack is wired correctly.

## Optional · Flink publish pipeline

Publish (`questionset/v4/publish`, Draft→Live) is **not required** — the LMS grades via `/play` +
`/submit`. To run it you need a Flink cluster plus the built job:

<AccordionGroup>
  <Accordion title="Cluster + job">
    Run `flink:1.13.6-scala_2.12-java11` as `flink-jm` (host :18081 UI) + `flink-tm` on
    `sunbird-local_default`. The fat jar `flink-runtime/questionset-publish-1.0.0.jar` (122 MB) is
    submitted with `flink run`.
  </Accordion>
  <Accordion title="Submit">
    ```bash
    docker exec flink-jm flink run -d \
      -c org.sunbird.job.questionset.task.QuestionSetPublishStreamTask \
      /rt/questionset-publish-1.0.0.jar --config.file.path /rt/qs-publish-local.conf
    ```
    Config (`flink-runtime/qs-publish-local.conf`): Kafka on the **internal** listener
    `sunbird-local-kafka-1:29092`, `schema.basePath=http://schema-http:8000`,
    `cloud_storage_type="cephs3"` (MinIO). Also create the Kafka topics and the `schema-http`
    container.
  </Accordion>
</AccordionGroup>

<Warning>
  The publish job is currently **blocked at the final Neo4j write** inside the Flink TaskManager
  (`ServiceUnavailableException`), so publish stays Draft. This does not affect authoring, playing
  or grading.
</Warning>
