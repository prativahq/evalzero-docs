## Fresh machine build

UserOrg (Lern) ships a **turnkey `build-and-run.sh`** — it builds, configures and starts the
service in one go. No manual dist/extract steps like inQuiry.

<Steps>
  <Step title="Prerequisites">
    Infra data layer up and the shared network present — `sunbird-local-cassandra-1`,
    `sunbird-local-redis-1`, `sunbird-local-elasticsearch-1`, `sunbird-local-kafka-1`.
  </Step>
  <Step title="Clone">
    ```bash
    cd ~/evalzero
    git clone https://github.com/prativahq/evalzero-sunbird-userorg.git lern
    cd lern
    ```
  </Step>
  <Step title="Build & run">
    ```bash
    chmod +x build-and-run.sh
    ./build-and-run.sh
    ```
    The script: patches property files for the `sunbird-local` container hostnames → builds all
    modules in Docker Maven → `play2:dist` the controller → extracts → writes a low-memory
    `application.conf` overlay → starts the container on **:9600** → polls `/health` until healthy.
  </Step>
</Steps>

<Warning>
  The build uses a **separate Maven cache volume** (`userorg-m2-cache`) on purpose — UserOrg and the
  LMS service both publish `org.sunbird:*:1.0-SNAPSHOT` artifacts (actor-core, platform-common,
  cassandra-utils, es-utils), so sharing `~/.m2` would clash. Don't "fix" it to reuse the default cache.
</Warning>

<Note>
  Manual build (from the README) uses the cloud-store flags:
  `mvn clean install -DskipTests -DCLOUD_STORE_GROUP_ID=org.sunbird -DCLOUD_STORE_ARTIFACT_ID=cloud-store-sdk_2.13 -DCLOUD_STORE_VERSION=1.4.8`.
  The Keycloak realm/client this service authenticates against is set up separately — see the
  `keycloak_local_setup/` guide in the repo and [Auth → Keycloak](/auth/keycloak).
</Note>

## Data prerequisites (fresh DB only)

<AccordionGroup>
  <Accordion title="user table columns">
    `sunbird.user` must carry UserOrg's columns (`flagsvalue`, `channel`, `maskedemail`,
    `maskedphone`, `alltncaccepted`) or reads 500. If a thinner table exists, `DROP TABLE
    sunbird.user` then re-seed.
  </Accordion>
  <Accordion title="Encryption">
    Set `sunbird_encryption=OFF` on the container, **or** all seeded email/phone must be
    AES-encrypted — otherwise profile reads NPE in the decrypt path.
  </Accordion>
  <Accordion title="System settings">
    `sunbird.system_settings` must contain `tncConfig` and `orgTypeConfig` rows (they're
    field-indexed, iterated by `DataCacheHandler.cacheSystemConfig`).
  </Accordion>
  <Accordion title="Channel id">
    `SUNBIRD_CHANNEL_ID` (`.env`) must match a real `sunbird.organisation.id`.
  </Accordion>
</AccordionGroup>

## Mock fallback (resilience)

<Info>
  The proxy silently falls back to mock user/org data on `ECONNREFUSED` / `ETIMEDOUT` / 5xx with a
  30s circuit breaker, so a UserOrg outage won't 502 the Profile page. Toggle with
  `USE_MOCK_USERORG` (defaults to `USE_MOCK`). Implemented in
  `server/src/routes/learner.routes.ts` (`makeUserorgProxy`).
</Info>
