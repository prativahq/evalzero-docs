**Sunbird RC** (Registry &amp; Credentialing) issues and verifies the **verifiable credentials**
behind EvalZero's certificates. When a learner completes a course, RC produces a cryptographically
signed certificate that anyone can verify — no need to trust the PDF or call our servers. It's a
self-contained compose stack and is **optional**: the LMS, assessments and auth all run without it.

## How it works (plain words)

Think of a **passport**: it carries a seal that's very hard to fake, and any officer can check it.
Our certificates work the same way.

<Steps>
  <Step title="We sign the certificate's data">
    The learner's name, course, completion date and grade are packaged as a **Verifiable Credential**
    (a W3C-standard JSON document) and **digitally signed** with a secret **private key**.
  </Step>
  <Step title="The private key never leaves the vault">
    That key lives locked inside **HashiCorp Vault**. Our services don't hold a copy — they send data
    *to* Vault and Vault returns a signature. Nothing to leak, nothing to steal.
  </Step>
  <Step title="Anyone can verify with the public key">
    The certificate carries a **QR code** and an issuer id (a **DID**). On scan, the verifier looks up
    the issuer's **public key** and checks the signature. Match → genuine. One edited character → the
    signature breaks → fake.
  </Step>
</Steps>

<Info>
  **Why not just a PDF?** A normal PDF can be edited in minutes. A signed credential **can't be
  forged** — the signature is mathematically tied to the exact values, and only our vaulted private
  key can produce it.
</Info>

## The signing chain

The services depend on each other bottom-up — this is also the order they must start in
(see [Dependencies](/rc/dependencies)):

```
Vault (holds private keys)
  └─ identity / DID (signs as an issuer, resolves public keys)
       └─ credential-schema (the certificate's shape)
            └─ credential (issue · verify · render PDF)
                 └─ registry / LMS (the API you call)
```

- **Vault** — the safe holding the signing keys. Boots **sealed**; must be unsealed each start.
- **identity** — the DID service. Creates the issuer identity, asks Vault to sign, and on verify
  resolves the issuer's DID to its public key. Certificate verification depends on it being live.
- **credential-schema** — stores what fields a certificate has.
- **credential** — issues, verifies and renders (PDF/SVG) credentials.
- **registry** — the core entity store and the main API surface.

## Services & host ports

RC's host ports are remapped to a **1xxxx band** (via `docker-compose.override.yml`) so it can
coexist with the other stacks on the box.

| Service | Container | Host port | Purpose |
| --- | --- | --- | --- |
| Registry (core) | `evalzero-sunbird-rc-registry-1` | `18091` | Entities / claims (`RC_BASE`) |
| Credentials | `evalzero-sunbird-rc-credential-1` | `13000` | Issue / verify / render (`RC_CRED_BASE`) |
| Credential schema | `evalzero-sunbird-rc-credential-schema-1` | `3333` | Schema service (`RC_SCHEMA_BASE`) |
| Identity (DID) | `evalzero-sunbird-rc-identity-1` | `3332` | Issuer DID create / resolve / sign |
| Vault | `evalzero-sunbird-rc-vault-1` | `8200` | Signing keys (boots sealed) |
| Keycloak | `evalzero-sunbird-rc-keycloak-1` | `18083` | RC's own realm (auth off for the cert flow) |
| Support | db · es · redis · kafka · zookeeper · minio | net / 1xxxx | RC's backing stores |

## EvalZero wiring (`.env`)

The LMS talks to RC over these — proxied in `server/src/routes/credentials.routes.ts`:

```bash
RC_BASE=http://localhost:18091         # registry
RC_CRED_BASE=http://localhost:13000    # credentials
RC_SCHEMA_BASE=http://localhost:3333   # credential-schema
RC_ISSUE_ENABLED=true
RC_ISSUER_DID=did:issuer:…             # who signs (created in RC)
RC_SCHEMA_ID=did:schema:…              # certificate shape
RC_TEMPLATE_ID=…                       # PDF/HTML render template
```

<Warning>
  RC brings its **own** Postgres, Vault, Keycloak, Elasticsearch, Redis, Kafka and Zookeeper — it
  does **not** reuse the `sunbird-local` infra. Bring the stack up with `./build-and-run.sh` before
  issuing a certificate, then `docker ps` to confirm registry / credential / schema / identity are
  healthy. If `RC_ISSUE_ENABLED=false`, you can leave RC stopped entirely.
</Warning>
