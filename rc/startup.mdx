<Info>Folder: **`~/evalzero/evalzero-sunbird-rc`** · Optional stack</Info>

RC is only needed when EvalZero issues or verifies certificates. One command brings up the whole
stack and configures V2 (Vault + DID + signing):

```bash
cd ~/evalzero/evalzero-sunbird-rc
chmod +x build-and-run.sh
./build-and-run.sh
```

The script: preflight (Docker + `.env`, bootstrapping from `.env.example` if missing) → pull the
upstream ghcr images → bring up the **shared infra** (db, keycloak, es, kafka, zookeeper, redis,
file-storage) → run `enable-v2.sh` (init/unseal Vault, enable KV, create the per-service DBs, start
identity/credential-schema/credential/claim-ms, restart registry with signing on) → `up -d` the
remaining services → verify health on the 1xxxx host band.

<Warning>
  Order matters: **Vault boots sealed**, so its healthcheck fails until `enable-v2.sh` unseals it —
  and `identity` has `depends_on: vault (service_healthy)`. A plain `docker compose up -d` therefore
  aborts with *"vault is unhealthy; dependency failed to start"*. That's why the script starts the
  infra first, unseals Vault via `enable-v2.sh`, and only then brings up the rest.
</Warning>

| Invocation | Effect |
| --- | --- |
| `./build-and-run.sh` | Pull ghcr images, up, enable V2 (issue/verify works) |
| `BUILD_IMAGES=1 …` | Build the images from source first (`make build` — heavy) |
| `SKIP_V2=1 …` | V1 only — skip Vault + the credential/schema/identity node services |

<Note>
  There's no `mvn` build here (unlike the Play services) — the override pins upstream
  `ghcr.io/sunbird-rc/*:${RELEASE_VERSION}` images. Re-running is safe: `enable-v2.sh` is idempotent
  and **re-unseals Vault** after a `docker compose down`.
</Note>

## Verify

```bash
docker ps | grep evalzero-sunbird-rc     # registry / credential / schema up?
curl -s localhost:18091/health | jq       # registry
curl -s localhost:13000/health | jq       # credentials
./demo-certificate.sh                      # end-to-end: issue → verify → PDF
```

<Note>
  RC brings its own Keycloak, Postgres, Elasticsearch, Redis, Kafka and Zookeeper — it does **not**
  reuse the `sunbird-local` infra. Expect a heavier startup than a single `docker start`.
</Note>

<Warning>
  If certificate issuance is off (`RC_ISSUE_ENABLED=false`) you can leave RC stopped entirely — the
  LMS, assessments and auth all work without it.
</Warning>
